# PC音声出力（v0.5.7）

「PCとDiscord」を選択した読み上げ・メディア・時報は、Botの参加済みVCがなければPCだけで再生します。未参加をエラーとしてキューを止めません。再生途中でVCから退出した場合もPC出力を続けます。Discordのみの設定では従来どおり接続先を確認します。マスタ再生は参加中のVCを共通の出力先にし、未参加でもPC側の再生は可能です。複数サーバーの宛先が不明な場合に別サーバーへ勝手に送信しません。

「設定」→「PCのスピーカーと通話音声」でスピーカーデバイスを選びます。VOICEVOX読み上げ・メディア・時報・通話音声のPC出力に共通です。以前の読み上げ用デバイス設定を自動移行します。USB機器の抜き差しと再取得に対応し、選んだ機器が使えない場合は既定のスピーカーで続けてログに残します。元の棒読みちゃんプロバイダーやAndroid仮想端末の直接再生は、それぞれの実行環境の音声設定を使用します。

## 1つのVCをPCで聞く

Discord接続でサーバーとBotのVC接続先を設定します。「PCで聞くVC（1つ）」でその接続先から1つを選択し、通話音量を設定・保存します。「通話音声を聞かない」で受信を止めます。選択したVCに人がいる場合は、通常の自動接続がオフでもモニター用にBotを接続します。無人時は「人がいなくなったら退出」の設定に従います。接続待ちと無音の待機をエラーにしません。1サーバーにつき1つのBot接続という制約を維持し、サーバーの接続先を変えるとモニターもその設定へ追従します。

選択した接続だけでBotの自己スピーカーミュートを解除し、`@discordjs/voice`の受信機能で各参加者のOpusを48kHzステレオPCMへ変換します。Bot自身のIDを購読対象から除外します。同時発話を合成し、PCのAudioWorkletへ40ms単位で送ります。受信音声はDiscordの送信ミキサーへ戻さず、ディスクにも録音しません。ユーザーごとのOpusデコーダー、ジッターバッファ、PC再生バッファを上限付きで管理し、最大32人を同時受信します。初期バッファの遅延は約360msにIPCと機器の遅延を加えたものです。

選択変更、無人退出、切断、終了時に受信ストリーム・デコーダー・PC再生を解放し、再接続時に選択したVCだけを受信し直します。VOICEVOX音声や通常の動画をBot自身の声として重複してPCへ流しません。

## 検証範囲

自動試験では、VCなしの「両方」設定からの連続読み上げ・動画・時報の実Electron音声を取得します。受信はDiscord受信ストリームを模した試験環境で実Opusをデコードし、PCのAudioWorkletからの音声・自己除外・デバイス設定保存・未接続デバイスの既定出力への切替を検証します。暗号化処理は既存のDAVE対応`@discordjs/voice`に任せます。Bot認証情報を使った実Discord VCの受信・参加者の機器までの音声は未確認です。
