# YouTubeログインとチャット再生（v0.5.1 / にゃんぷれいv0.2.2）

## ログインの操作

GoogleはElectronの組み込みブラウザからのログインを「このブラウザまたはアプリは安全でない可能性があります」と拒否することがあります。YouTubeのログインは通常のChrome / Edgeで行い、利用者が引き継ぎを指示します。単に外部ブラウザでログインするだけではアプリへ引き継がれません。

1. Releaseのにゃんとーくv0.5.1と、にゃんぷれいv0.2.2を更新します。拡張はZIPを展開し、Chrome / Edgeの拡張管理から読み込むか更新してください。
2. アプリの「再生アカウント」でYouTubeを選択し、「ログイン画面を開く」を押します。通常のChrome / EdgeでYouTubeへログインします。既定のブラウザが別の場合は、にゃんぷれいを入れたChrome / EdgeでYouTubeを開いてください。
3. アプリのコピーアイコンで接続コードをコピーします。にゃんぷれいの猫アイコンを押して設定を開き、接続コードを貼り付け、「にゃんとーくへ引き継ぐ」を押します。表示されるCookie・同一PC接続の権限を許可します。
4. アプリに「YouTubeのログイン情報を受け取りました」と表示されたら、再生を試してください。失敗した項目は履歴から再実行できます。

再生中のYouTubeウィンドウは停止してから引き継ぎます。接続コードは10分間・1回限りです。ログインが失効した場合は再度引き継ぎます。Chrome側でログアウトしても、すでに引き継いだアプリ側のセッションが即時に削除されるとは限りません。アプリ側のログアウトは再生画面のYouTubeで操作してください。

YouTubeのCookieだけを、127.0.0.1に限定したアプリの待受けへ送ります。Cookie、パスワード、接続コードをDiscordやGitHubへ送りません。GoogleのパスワードやGoogleドメインのCookieは読み込みません。引き継いだCookieは、既存のElectron再生用Cookie領域に保存し、通常再生・全サーバー・時報BGM検索で共有します。Premiumや公開範囲などはサービス側が判断します。「受け取りました」は保存完了を表し、Google認証や契約状態の確認完了を表しません。

## チャットから再生されない場合

v0.5.0までは通常の読み上げ対象にチェックしたチャンネルでのみ再生命令も受け付けていました。v0.5.1ではVC接続先を設定したサーバーの、Botが閲覧できる全テキストチャンネルで受け付けます。通常の読み上げはチェックした対象だけです。マスタチャンネルは従来どおり全サーバー共通、それ以外は投稿されたサーバーのVCへ出力します。

対応形式は `URL再生`（告知後45秒）、`URL無限`（告知後1回全編）、`URL直接`（告知なし1回全編）、および `NYANPLAY/1 {JSON}` です。URLと指定の間に空白を入れた形式、`<URL> 無限` も受け付けます。開始位置とタイトルを保持します。

イベントログでキュー登録、VC未設定、メディア受信OFF、不正形式を確認できます。URL投稿の本文が取得できない場合はDiscord Developer PortalのBot設定で **MESSAGE CONTENT INTENT** を有効にし、Botを再接続してください。Botの「チャンネルを見る」「接続」「発言」権限も必要です。告知付きモードは音声エンジンを必要とし、告知の合成に失敗するとイベントログに失敗を表示します。

## 検証

`npm test`で受信対象外の読み上げチャンネルから3モード・固定スキーマが一度だけ登録され、サーバー・送信者の除外が維持されることを確認します。Cookieの対象、有効期限、接続元、接続コード、不正要求・再送を検証します。

`npm run verify:account-link`は実Chrome拡張と実Electronアプリを使い、設定画面→service worker→同一PCのHTTP待受け→保存→再起動→再生ウィンドウの共有を確認します。試験用Cookieのみを用い、任意権限を事前許可した試験用manifestを使います。製品の権限承認ダイアログ、実Googleアカウント、Premium適用、実YouTube本編の音声、実Discord VCへの到達はこの試験では確認しません。
