# 時報

「時報」で毎正時の時報を有効にします。時計は常駐Windows PCのローカル時刻です。共通時報の送信先は、その時点でBotが参加している全サーバーのVCです。マスタチャンネルの共通再生と同じ送信範囲を使い、テキストへの投稿は行いません。

## 共通時報と優先順位

`にゃんとーくが〇〇時をお知らせします`をVOICEVOXで準備し、短い440Hzの音を正時の2秒前・1秒前、長い880Hzの音を正時に開始します。合成した告知の長さに応じて開始時刻を決め、3点目の開始位置を正時に合わせた一つのPCM音声として予約します。Discordは48kHzステレオの20msパケット、PCはAudioContextの予約再生を使用します。通信・出力機器の遅延が加わるため、利用者のスピーカーでの完全な時計一致は保証しません。PCの時計はWindowsで同期してください。

時報は停止告知を含む通常の読み上げより優先します。再生中の読み上げを中断し、待機中の項目は保存します。共通時報後、生成文のないサーバーの待機読み上げを再開します。生成文のあるサーバーはその完了後に再開します。中断した読み上げの自動再読は行いません。

再生中のメディアは、設定した割合まで音量だけをフェードします。再生位置は進め続け、終端に達したメディアは通常どおり終了します。時報後は残っているメディアの音量を戻します。終了したメディアを開き直したり、先頭から再生したりしません。

音声準備が間に合わない場合、遅れた共通時報は流さずログに残します。スリープ復帰時にも過去の時報を再生しません。「15秒後を正時として試す」で予約再生を試し、「中止」で準備・再生を中止できます。

## 文章生成と資料

サーバーごとに「生成文を読み上げる」を有効にし、資料チャンネルをチェックボックスで複数選びます。通常の読み上げ対象とは別の選択です。Botにはチャンネルの閲覧・メッセージ履歴の閲覧とMessage Content Intentが必要です。

初回はDiscord APIで100件ずつ過去へ取得し、閲覧可能な全履歴を対象にします。件数の先頭切り捨ては行いません。中止後は取得済みの位置から再開します。以後は差分取得と受信イベントで新規投稿・編集・削除を反映します。取得中に新しいメッセージが届いた場合も重複しません。オフライン中の削除や編集はDiscordからイベントが届かないため、既存キャッシュとの差異が残る場合があります。「取得履歴を削除」して再取得すると現在の履歴に合わせられます。

kuromojiで単語を分解し、メッセージID・時刻・単語情報をユーザーデータの`hourly-history.sqlite`へ保存します。生の投稿本文を保存せず、設定のエクスポートにも履歴や生成計画を含めません。生成時点の取得済み履歴を使い、初回の全履歴取得が未完了の場合は共通時報のみ流します。生成開始後に届く投稿は次回の資料になります。

全資料の名詞頻度から異なる2語を毎回選び、ローカルSLMに主語・目的語・述語・形容詞をJSONの文法構造として選ばせます。主語と目的語を分け、他動詞と格助詞を組み合わせた短い日本語文にします。意味の意外な組み合わせを楽しむ方式です。生成文に資料の名詞2語が実際に含まれるかも形態素解析で確認します。不正な構造は読み上げずログへ残します。

## ローカルSLM

「SLMを導入・更新」で公式OllamaのWindows x64配布を取得します。GitHubの配布SHA256を検証し、アプリのユーザーデータ内へ展開します。実行環境とモデルには数GBの空き容量が必要です。既定のモデルは日本語を扱える`qwen3:0.6b`です。取得後の文章生成はPC内で行い、Discordの資料を外部の生成APIへ送信しません。

管理するSLMは`127.0.0.1:11489`だけで待ち受けます。既存OllamaのループバックURL・別モデルも指定できます。モデルの初回取得と実行環境の更新にはインターネット接続が必要です。アプリ終了時にはアプリが起動したSLMプロセスだけを停止します。利用者が別に起動したOllamaは停止しません。

「文章生成を試す」で生成時間を測れます。共通時報の告知開始から3点目の終了までを生成時間の予算にし、既定の自動設定では予算を超える場合に日次生成へ切り替えます。日次ではその日の24時刻分を一度生成して`hourly-plans.json`に保存し、該当時刻の文章を順に使います。この方式の資料の締め切りは日次生成開始時です。都度生成は共通時報の開始時点の資料を使います。明示的に「都度生成」「1日分を事前生成」も選べます。

生成・履歴取得・SLM導入の失敗が、共通時報を止めることはありません。

## BGM

生成文中の名詞2語に`フリーBGM`を加えて、内部ブラウザと同じアカウント領域でYouTubeを検索します。広告枠を除く通常動画の先頭候補を、通常メディアとは別の再生ウィンドウ・音声バッファで再生します。検索語はYouTubeへ送信されます。

BGMは初期値3秒でフェードインします。開始を確認してから生成文を読み、読み終わった1.5秒後から初期値3秒でフェードアウトし、無音で停止します。両方の時間は「時報」で0〜30秒の範囲で変更できます。BGMが先に自然終了した場合も再再生しません。ログイン要求・検索失敗・再生失敗時はBGMを省いて生成文を読みます。「再生アカウント」でYouTubeへログインしてください。検索結果の利用許諾は検索語だけでは確定しません。

Discord出力では各サーバーの生成文とBGMを並行再生できます。PCへの出力を含む場合、PCの一つの出力装置で複数文章が重なるのを防ぐため、生成文をサーバー順に流します。
