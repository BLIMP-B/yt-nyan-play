# メディア配信と音量

「設定」の「音声のみの配信を優先し、なければ最低画質で再生」は既定でONです。Windowsで初回利用時に公式yt-dlp（約18MB）を取得・SHA256検証し、アプリの再生アカウントを使って配信形式を調べます。音声専用形式があればそれを、なければ音声付きで高さ・帯域の小さい動画形式を選びます。FFmpegで音声を取り出し、同じPCの一時URLから内部プレイヤーへストリーミングします。動画全体を保存せず、Discordへの音声取り込みとPC出力に同じ経路を使います。URLの開始位置も反映します。「再生」だけ45秒に制限し、「無限」「直接」は終端まで1回再生します。

| サービス | 配信形式の選択 |
| --- | --- |
| YouTube | 音声専用形式を優先。利用できなければ音声付き最低画質 |
| ニコニコ動画 | 音声専用形式が返れば使用。通常は音声付き最低画質のHLS等 |
| X / Twitter、Instagram、TikTok、Facebook、Threads | 投稿の音声専用形式が返れば使用。通常は音声付き最低画質 |
| Bluesky | 音声専用形式、または最小の音声付き動画 |
| Mastodon | 投稿と同じホストから取得できる形式。別ホストの添付はブラウザ再生 |

ログイン、地域、配信元の形式変更などで取得できない場合は通常のブラウザ再生へ戻ります。YouTubeの品質APIとvideo.jsの品質APIがあれば最低画質を指定します。画質APIがないページでは設定を強制できないためログに表示し、再生ウィンドウでサイトの画質設定を使用します。ライブ・DRM・動画のみの形式はこの音声配信経路で処理せず、ブラウザへ戻します。音声がない投稿は無音のままです。OFFにすると最初からブラウザ再生になります。

再生アカウントのCookieは取得プロセス用の一時ファイルへサービス別に渡し、終了後に削除します。元のURL・開始位置・案内・全編1回・後着優先・サーバー別とマスタ再生の区分を保持します。取得時間超過もブラウザへ戻します。新しい再生や停止で進行中の取得・配信を中断します。

v0.5.2では、音声プレイヤーの終了と元動画の終了を区別します。取得した動画の長さ・FFmpegの出力時間・実際の再生位置を照合し、配信の途中終了や転送エラーの場合は、再生済みの位置から元ページで継続します。この切り替えは1回で、告知を繰り返しません。「再生」は残りの秒数だけを引き継ぎ、合計45秒を維持します。「無限」「直接」には時間制限を設けません。正常な終端では停止し、開き直しません。長さが取得できない場合は、正常な配信終了を終端として扱います。継続にログインが必要な場合は「再生アカウント」から引き継いでください。

通常メディアは読み上げ開始時に「読み上げ中の動画音量の割合」へ減衰し、読み終わりに元の音量へ戻します。減衰時間と復帰時間は初期値各3秒です。割合0.05なら元の動画音量の5%です。「設定」で時間を0〜30秒の範囲で変更できます。

時報BGMのフェードイン・アウトも初期値各3秒で「時報」で変更できます。カスタム文章を読み終わってから1.5秒待ち、設定した時間で消して停止します。フェード中も動画の位置は進み、自然終了したら再再生しません。

自動試験は9サービスの形式選択、実FFmpegの開始位置・音声生成・自然終了、実Electronの音声配信取り込みを対象にします。長時間試験は62秒のメディアを7秒位置から、正常配信・途中終了のそれぞれで3方式とも再生し、音声と自然終了、ブラウザ継続時の残り時間を確認します。公開サイトの実音声検証は別のCI結果に記録し、取得できなかったサイトを成功とは扱いません。実アカウント認証と実Discord VCへの到達は利用者の環境で確認が必要です。
