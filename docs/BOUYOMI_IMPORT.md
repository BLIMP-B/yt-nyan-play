## 実装した取り込み

「読み方の辞書 → ZIPから取り込む」でアプリのユーザーデータ内 `bouyomi/` へ展開します。元の設定・辞書・素材をバイト単位で維持し、再取り込み時は前のフォルダを日時付きバックアップへ移動します。原本を上書きしません。辞書の構造・件数と設定を読み取り、取り込んだ通信ポートをアプリへ反映します。取り込み操作だけでは本体を実行しません。

「元アプリを起動」で取り込んだWindows実行ファイルを起動します。「元アプリを終了」はウィンドウへ終了要求を送り、設定や教育辞書の保存機会を保ちます。元アプリの編集画面では全ての設定・辞書を編集できます。旧PCの絶対パス・外部AHK・インストール済みSAPI音声等は別環境で自動解決できません。

棒読みちゃんを選んだ場合、原文送信モードではDiscord本文の記号・タグ・教育文を加工せず送ります。元アプリの辞書、.NET正規表現、タグ生成の条件、教育・忘却をそのまま本体に処理させます。送信時の声0、速度/音程/音量-1で元アプリの設定を使います。既存の共通辞書のRE2処理へ変換しません。

直接チャットに書いた `(Study ...)` 等がそのまま命令になるとは扱いません。元ReadMeに従い、タグ辞書で置換されたタグだけを本体が処理します。Studyで同じ文字列を指定した場合の忘却、Forgetが教育辞書だけを削除する動作も本体へ委ねます。Command・Sound系タグの動作は取り込んだ設定とパスに従います。

## 検証と残り

実際の共有ZIPを取り込んで、12辞書のSHA-256・設定の値・466規則を確認しました。自動試験ではZIPの直下/フォルダ構成、バイト保持、バックアップ、教育文の原文保持、TCPプロトコルを確認しています。

この作業環境はLinuxで、Windows仮想環境は付属していません。棒読みちゃん本体をWindowsで実際に開く検証、実教育・忘却・全タグの比較試験はまだ行えていません。Windows版にゃんとーくのビルド・画面試験と、元の棒読みちゃん本体の実行試験を区別します。

本体経由はローカル再生です。VOICEVOXへ全辞書・.NET正規表現・音声記号・タグを完全に移植した実装ではありません。Discordへの棒読みちゃん音声取り込み、元の配信者向け機能を新UIから変更する機能、全機能の再実装は残っています。完全互換を検証済みとは表記しません。

元ReadMeは「本ソフトウェアの無許可での再頒布は禁止」と記載しています。そのため元本体の公開同梱をせず、利用者が保有するZIPからのローカル取り込みを実装しています。個人のTwitter認証値・履歴・辞書をCIや公開ソースへ送信しません。

## v0.4.0のVOICEVOX前処理経路

新規取り込みではVOICEVOXとDiscord出力を選び、`bouyomiPreprocess` を有効にします。原本の設定値を変更せず、Windowsの.NET Framework上の自作x86ヘルパーが、取り込んだ元アセンブリの公開変換APIを呼びます。前処理の単純・正規表現置換、文字種統一、タグ生成、教育・単語置換、短文化に元実装を使います。.NET正規表現をRE2へ翻訳しません。元アプリのUI・再生スレッドは起動せず、得た文章をVOICEVOXへ渡し、BotのDiscord音声へ直接送ります。元アセンブリ・個人辞書はパッケージに同梱せず、ユーザーが取り込んだものだけを参照します。

VOICEVOXが普通の文章を受け取るため、原本のSAPI経路と同じくMSIME/AquesTalkの音声記号変換、Talk/Post置換はこの経路では実行しません。12辞書の原形式はすべて保存します。原本のVOICEVOX接続方法とSAPI声登録状況が回収できていないため、実機上の経路一致は確認待ちです。

「配信者向け機能」は元設定／有効／無効から選べます。元設定では現在のfalseを保持します。有効にすると辞書が生成したStudy/Forget、声・話速・音程・音量タグ等を処理します。チャットに直接書いたタグを命令として解釈しません。教育・忘却は原アセンブリのAddRule/RemoveRule/SaveRuleで教育辞書だけを更新し、初回更新前の辞書を `.before-damare` に保管します。同時処理による上書きを防ぐため、ヘルパーへの要求は順番に処理し、元アプリ起動中は前処理を実行しません。

`bouyomiUseDefaults` が有効なら元の速度139・音量100・音程100を合成パラメータへ反映し、元の文字数制限が無効なら新アプリのmaxChars=500で途中切り捨てを行いません。加速は待機・処理中の元文章の累積文字数をサーバーごとに数えます。Speed/Tone/Volumeタグは元設定を基準に倍率と制限を適用します。エンジンの違いによる速度・音程の音響的一致は実音声で照合する必要があります。

元の声番号とVOICEVOX style IDは自動で同一視しません。設定JSONの `speech.bouyomiVoiceMap` に `[{"voiceId":10008,"styleId":3}]` 等を指定します。この例は形式だけを示し、ユーザーの声番号16の実際の声が10008/ノーマルであることを示すものではありません。Voiceタグの9〜999という旧SAPI短縮指定は原本と同じく9992を加えたIDへ解決します。

Sound/SoundW、Info VERSIONの経路も追加しています。Command/CommandW、Reverb、左右別Volume、その他Info、AA省略、滞留スキップ等はVOICEVOX統合経路では未対応で、対応表へ残します。実装済みの各タグも原本とのWindows比較は未完です。未対応タグはジョブのエラーとして表示し、処理済みのように無視しません。完全互換を満たすまではこの経路を互換確認中として扱います。

ネイティブヘルパーは.NET Framework 4.8向けx86でコンパイル確認し、Windows CIでもx86コンパイルとJSONエラー応答を確認します。元のBeta21をWindowsで起動して比較する試験は、この環境にWindows仮想PCがないため未実施です。原本を使わない自動試験と、この比較試験を混同しません。

共通の全体・サーバー・利用者辞書は、元の変換を終えた発話文に追加適用します。生成タグの種類・引数は変更しません。サービス別告知と停止告知は辞書を通さず、取り込み元の基本音声設定を共有します。

## v0.4.4のチャット教育・忘却・無音

読み上げ対象チャンネルで `教育(単語=読み方)`、`忘却(単語)`、`無音(単語)` を受け付けます。括弧・等号は全角半角とその混在に対応します。「チャットの教育・忘却・無音を受け付ける」は既存設定にも既定で有効となり、元の `BroadcasterMode=false` によって無効にはなりません。通常の読み上げと同じチャンネル・利用者の受信設定を適用し、結果をチャットと音声で返します。

取り込んだ原アセンブリのVOICEVOX前処理が有効なら、元の文字種統一APIと教育辞書のAddRule/RemoveRule/SaveRuleを使います。最小入力長・最大読み長・教育と忘却の応答書式も元設定から取得します。`無音` は教育辞書の読み方を空にして保存します。配信者向けタグ機能が無効でも、教育辞書は後続の文章に適用します。元アプリ起動中の競合更新は受け付けません。

原アセンブリを利用しない構成では、設定の独立した `education` 配列へ保存します。全サーバーで共有し、バックアップ・再起動後にも保持します。通常辞書を消さず、教育規則だけを忘却します。再教育は同じ単語を上書きし、単語と同じ読み方の教育は忘却として扱います。この構成の既定制限も入力2文字以上・読み15文字以下です。ネイティブの全置換挙動との完全一致はWindows原本比較の確認対象に残します。
