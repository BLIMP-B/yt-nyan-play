# 送信側Chrome拡張の拡張仕様

更新日: 2026-10-05。今後の実装仕様です。今回取り込んだv0.1.2の対応先はYouTubeです。

## 維持する操作

**ページに再生できるメディアがある場合にボタンを表示し、ボタンをクリックすると送信画面が開く**流れを維持します。メディアを検出しただけでは送信せず、利用者が送信先と内容を確認して送信します。

利用者の「嗄声できるメディアファイル」という記述は、前後の動画・ブラウザ再生の文脈から「再生できるメディア」と解釈しています。

送信画面にはメディア候補、タイトル、送信先、開始位置、再生／無限の指定、送信内容のプレビューを置きます。宛先の複数選択と設定画面への導線を維持し、ページ内に複数の動画・音声があれば送る対象を選べるようにします。

## 対応先

| 対応先 | 方針 | 状態 |
| --- | --- | --- |
| YouTube通常動画・Shorts | 既存の導線を維持し、共通検出層へ移す | v0.1.2の実装あり |
| ニコニコ動画 | 動画ページのURLとプレイヤー情報を取得 | ユーザー指定。今後実装 |
| 各種SNS | 投稿単位で動画・音声を検出し、投稿URLと対象を送る | ユーザー指定。サイトごとの実装が必要 |
| 一般のHTML動画・音声 | `video` / `audio` / `source`の情報から候補を検出 | 今後実装 |
| 直接のメディアURL | ブラウザが再生可能な音声・動画を候補にする | 今後実装 |

SNS候補はX、Instagram、TikTok、Facebook、Threads、Bluesky、Mastodon等です。これは優先順位を決めるための候補であり、対応済み・全サイト動作保証とは扱いません。SNS名だけで一括対応せず、各サービスの動画・音声投稿を個別に検証します。

## 検出とボタン表示

共通の検出層とサイト別アダプタを分けます。共通層はメディア要素、ロード状態、メタデータ、再生可能な形式を調べます。サイト別アダプタは投稿URL、動画ID、タイトル、複数候補の区別とボタン位置を補います。

`video` / `audio`が存在するだけで再生可能と断定せず、実際のソースやプレイヤー状態を確認します。拡張子のみの判定を避け、遅延読み込み、動的な`src`変更、SNSの画面遷移、DOMからの削除に追従します。検出は間引き、同じメディアに重複したボタンを作りません。

既存のYouTubeでは操作領域のボタンを維持します。他サイトではプレイヤー・投稿の近くにボタンを置き、サイト別の配置が難しい場合は対象を選ぶ共通パネルを用意します。フレーム内のメディアは権限と取得可否を踏まえて対応し、メディアが消えた場合は候補とボタンも更新します。

ページ内のメディア検出と、別の再生端末で利用できることを分けて扱います。認証・地域・配信条件により再生先で開けない場合は、送信画面や受信側で理由を表示します。

## 送信する情報

基本情報は`pageUrl`、対象候補ID、タイトル、サイト種別、動画／音声の種別、開始秒数、ループ指定です。直接再生できる永続URLが取得できる場合に限り`mediaUrl`も送ります。

`blob:`や`MediaSource`のURLはそのブラウザ内に限定されるため、単独の再生先URLとして送信しません。SNSの投稿URLや動画IDを使い、デスクトップ側のサイト別再生処理で解決します。期限付きURLを恒久的な履歴として扱わず、ログインCookieやブラウザの認証トークンは送信情報へ含めません。

仕様バージョンとリクエストIDを持たせ、DiscordのメッセージIDと合わせて再送や重複を管理します。既存の受信側に向けた`URL＋再生/無限＋タイトル`形式も移行期間は選べるようにします。SNS・ニコニコにはYouTube専用の`youtu.be`変換を適用しません。

「最初から」は明示的な開始位置0として扱い、サイト固有の時刻指定が残って矛盾しないようにします。「現在位置」は選んだメディアの時刻を使います。複数動画があるページで最初の`video`要素を一律に採用する方式は改めます。

## 権限・送信結果

サイト対応に必要なホスト権限をアダプタとセットで追加し、一般ページは利用者が有効にする追加権限で扱う設計を検討します。特定のSNS対応を目的に、最初から全ページへの権限を必須にする構成は避けます。今回のv0.1.2にはSNS用権限をまだ追加していません。

送信完了は宛先ごとの結果を確認して表示します。一部失敗した場合は成功した宛先と失敗した宛先を分け、失敗先だけ再試行できるようにします。送信ボタンの待機解除と実際の送信成功を区別し、履歴には成功・失敗・保留を記録します。

## 受け入れ条件

- 対応ページで再生可能な動画・音声を検出し、候補に対応するボタンから送信画面を開ける。
- 複数候補、遅延読み込み、SNS内の画面遷移でも対象URL・タイトル・開始位置が正しい。
- 宛先を選ぶまで送信されず、検出だけで自動送信されない。
- YouTube、ニコニコ、優先SNS、一般の動画・音声について、上流拡張から下流アプリまで送信・再生を確認する。
- 利用できないメディアや再生失敗について、利用者が理由と次の操作を確認できる。
- 既存の設定・送信形式との互換性を検証し、失敗を成功扱いする表示を改善する。
