# にゃんぷれい v0.2.1

更新日: 2026-10-06（日本時間）。Chrome Manifest V3の送信側拡張です。

## 操作

対応サイトでソースが設定された動画・音声を検出し、対象メディアの近くに「再生」を表示します。YouTube通常動画では従来の操作領域を使います。ボタンを押すと対象・再生方式・開始位置・送信先を選ぶ画面が開きます。検出や画面を開くだけでは送信しません。

- **再生**: サービス名の読み上げ後に45秒再生。
- **無限**: サービス名の読み上げ後に全編を1回再生。
- **直接**: 案内の読み上げなしで全編を1回再生。
- **最初から**: URLに残っていた時刻指定を除去。
- **現在位置**: 選んだメディアの時刻を整数秒で取得。ニコニコは`from`、他サイトは`t`。

複数のメディアがあるページでは選択欄から対象を切り替えます。各候補の投稿URLを使い、タイムラインのURLを一律に送らない構造です。Shadow DOMでサイトCSSから操作画面を分離し、明るいページ・暗いページと390px幅の画面で表示を試験します。

## 対応アダプタ

| サイト | 取得対象 |
| --- | --- |
| YouTube | 通常動画・ShortsのURLとタイトル |
| ニコニコ動画 | `sm` / `so` / `nm`動画のURLとタイトル |
| X | 動画・音声を含む投稿の`status` URL |
| Instagram | `p` / `reel`投稿 |
| TikTok | `@利用者/video/ID` |
| Facebook | 動画・Reel・WatchのURL |
| Threads | threads.com / threads.netの投稿 |
| Bluesky | `profile/利用者/post/ID` |
| Mastodon | 投稿のパーマリンク、動画・音声 |

アダプタの実装、試験用DOMでの検証、実サイトでの検証は[検証記録](EXTENSION_VERIFICATION.md)に分けて記載します。表は全サービスでの実再生保証を意味しません。画像・文字だけの投稿、ソースのないプレイヤー、YouTube広告再生中のプレイヤーにはボタンを出しません。アクセス制限・非公開投稿・期限付きメディア・DRMは、受信側でも利用条件を満たす必要があります。

一般のHTML動画・音声と別のMastodonインスタンスは、設定の「追加のメディアサイト」にURLを入力し、Chromeの確認でそのサイトだけを許可してください。追加権限は登録・解除でき、対象タブの再読み込み後に反映します。全サイトへの読み取り権限は既定で要求しません。

## 検出と配置

`media-adapters.js`がソース・プレイヤー状態、メディアに近い投稿リンク、タイトルを取得します。`content-script.js`は候補ごとのボタンと共通送信画面を扱います。DOM変更は間引いて調べ、ソースの遅延設定、SPAのURL・投稿リンク変更、対象の削除に追従します。画面外・非表示のメディアではボタンを隠し、同じ要素へ重複して作りません。

SNSではプレイヤー右上のボタンをページに重ねるため、サイトのレイアウトを変えません。サイト固有の浮動操作と重なる場合や、iframe・閉じたShadow DOM内のメディアは未対応です。複数の動画を同じ投稿URLで公開しているサイトでは、受信PCが同じ候補を選ぶことまでは保証していません。

## 送信と履歴

既存のPC版と互換性を保つため、`URL＋再生/無限/直接`とタイトルを送ります。YouTubeの全編モードだけ`youtu.be`へ変換し、SNS・ニコニコへは変換を適用しません。`blob:`、Cookie、ログイントークンは送信しません。一般サイトはページURLを送るため、受信側で開けるページである必要があります。

宛先は複数選択でき、送信先ごとの成功・HTTPエラー・タイムアウトを表示します。一部失敗した場合は成功先へ再送せず、失敗先だけを再試行できます。既存の宛先設定を維持し、成功した履歴だけを保存します。Webhookの完全なURLは表示・履歴でマスクし、本文由来の文字列をHTMLとして解釈しません。通知やメンションは送信先で自動展開しない指定です。

履歴はChrome同期ストレージに直近20件保存します。容量上限による保存失敗は表示します。ネットワーク切断時はサーバーでの受理を判定できない場合があるため、再送の重複を完全には防ぎません。

## 試験・配布

`npm run check`、`node --test tests/extension.test.mjs`、`npm run verify:extension`、`npm run package`を使用します。表示試験にはPlaywright用Chromiumの導入が必要です（`npx playwright-core install --with-deps chromium`）。管理ポリシーで拡張追加が禁止されたChromeでは試験できません。

GitHub Actionsは実際のMV3拡張を読み込んだ制御された投稿DOMで表示・操作を検査し、別の新規プロファイルで実公開ページを調べます。試験条件と未確認事項を記録し、画像・報告・`yt-nyan-play-0.2.1.zip`をGitHub Releasesに配置します。

## v0.2.2のYouTubeログイン引き継ぎ

設定画面の明示操作でのみ、任意の`cookies`権限と`http://127.0.0.1/*`を要求します。設定画面由来であることをservice workerで確認し、`youtube.com`のCookieだけを読みます。接続コードで指定できる送信先は固定の127.0.0.1とポートのみで、URL・ホストを任意指定できません。CookieをDiscord、拡張の同期ストレージ、ログ、ファイルへ送信・保存しません。10分・1回限りの接続コードでアプリへ送り、YouTube用の永続再生領域へ保存します。GoogleのCookieやパスワードは取り込みません。
