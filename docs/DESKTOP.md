# にゃんとーく〜Damare〜 v0.4.3

「にゃんとーく〜Damare〜」は、常時稼働するWindows PC上で、Discord.js Bot、読み上げ、専用ブラウザによるメディア再生を一つのElectronアプリから操作します。Node.js、Discord.js、Opus、FFmpegはインストーラーに含まれ、利用者のPCにNode.jsやAHKを別途導入する必要はありません。

## 導入と初回設定

1. GitHub Actionsの **Desktop tests and Windows package** で成功した実行を開き、`nyan-talk-damare-windows-x64` 成果物を展開します。`NyanTalk-Damare-Setup-0.4.2-x64.exe` がインストーラー、ZIPが展開して利用する版です。Windows 10/11 x64を対象にしています。現在の配布物はコード署名を行っていません。
2. VOICEVOXを導入して起動するか、VOICEVOX Engineの `run.exe` を「声と読み上げ」で選択します。既定のAPIは `http://127.0.0.1:50021`。実行ファイルを選んだ場合はアプリがエンジンを起動・終了します。エンジンとモデルの同梱はこの版では未実施です。
3. Discord Developer PortalでBotを作成し、**MESSAGE CONTENT INTENT** を有効にします。Botをサーバーへ招待し、対象チャンネルで「チャンネルを見る」「メッセージ履歴を読む」「メッセージを送信」「接続」「発言」を許可します。管理者権限を与える必要はありません。
4. 「Discord接続」でBotトークンを保存して「Botを開始」。トークンはWindowsのDPAPIで暗号化して保存し、画面・設定のエクスポートには戻しません。
5. 「Discord接続」のサーバー一覧でBotの音声接続先を選択し、読み上げるテキストチャンネル・VC内テキストにチェックを付けます。カテゴリ別にチャンネル名を表示し、選択は自動保存します。複数サーバーを個別に設定できます。Botが閲覧・接続できないチャンネルは選択できません。IDを指定する従来の入力は「IDで手動設定」に残しています。
6. 「声と読み上げ」で声種を読み込み、出力をPC・Discord・両方から選びます。「ずんだもん全声種を確認」は8つのトークスタイルの存在と実際の合成API応答を確認します。
7. Chrome拡張のWebhook送信先を、Botが受信するテキストチャンネルに合わせます。ダッシュボードからURL追加とテキスト合成も試せます。

Chrome拡張はインストール先の `resources/chrome-extension` にも同梱します。Chromeの拡張管理からユーザーが読み込んでください。v0.1.2の拡張はYouTube向けです。SNS・ニコニコ用の検出ボタンは今後の拡張側の実装です。PC側では許可ホスト上のHTML5 video/audioを操作する共通再生処理を用意しています。

## 操作

画面を閉じると既定ではトレイに格納し、Botは継続します。トレイから表示・Bot開始・停止・アプリ終了ができます。「Windowsにログインしたら起動」と「アプリ起動時にBotを接続」は個別に設定します。Windowsサービスではなく、ログイン中のユーザーセッションで常駐します。画面ロック中の動作は継続できますが、ログオフ・PC停止・スリープ中には動作しません。

読み上げとメディアはサーバーごとに順番に処理し、他のサーバーを待たずに実行します。動画中の読み上げでは設定した割合へ動画音量を下げます。「一時停止」は新規処理と動画再生を止め、処理中の読み上げは完了させます。「次へ」は現在のメディアをスキップ。「すべて停止」は処理中と待機中を取消します。履歴から再実行できます。「無限」は繰り返しを意味せず、開始位置から終端まで1回再生します。45秒制限は「再生」だけに適用し、読み込み・バッファリング・一時停止中の時間を含めません。旧設定のmaxMinutesは互換読込み用に残し、全編再生を途中で打ち切るためには使用しません。

辞書は全体・サーバー・利用者単位で設定でき、正規表現はRE2で処理します。声種と話速は利用者別に変更できます。名前・URL・絵文字・添付・コード・ネタバレの扱い、読み上げテンプレート、利用者・ロールの除外、許可する利用者、NGワードを設定できます。`emojiReadings` の個別読みは設定JSONから登録できます。音声クリップは指定した文章と一致したときに再生します。

Webhook受信と他Botの読み上げは別に設定します。既定ではWebhookを受信し、他Botと自分のBotの文章は読み上げません。設定したチャンネルだけを受信し、必要ならWebhook IDを制限できます。

棒読みちゃんのTCP / HTTP送信も用意しています。VOICEVOXの声種番号とは別に棒読みちゃんの声番号を設定します。棒読みちゃんは外部アプリでのローカル再生であり、音声終了の検知・Discord送信・クリップ再生はこの経路では提供していません。

## Discordコマンド

接頭辞は既定で `!nyan`。設定済みチャンネルで受け付けます。返信ではメンションを通知しません。

| コマンド | 動作 | 権限 |
| --- | --- | --- |
| `help`, `status`, `speakers` | 説明・状態・声種の一覧 | 全利用者 |
| `voice <声種ID>`, `speed <0.5〜2>` | 自分の声・話速を保存 | 全利用者 |
| `join`, `leave` | 設定した音声チャンネルへ参加・退出 | 管理操作 |
| `pause`, `resume`, `skip`, `stop` | キュー・動画の操作 | 管理操作 |
| `play <URL>`, `loop <URL>` | 告知後45秒・告知後終端まで1回を追加 | 管理操作 |
| `dict <単語> <読み>`, `dict-list`, `dict-remove <単語>` | サーバー辞書の編集と表示 | 管理操作 |

管理操作はDiscordのサーバー管理権限、または設定に登録した利用者IDが必要です。音声入室・退出・移動の通知、自動接続、人がいなくなった場合の退出にも対応します。DM設定は **このBotに送られたDM** が対象で、利用者個人のDM・グループDMを取得する仕組みではありません。

## 送信形式と再生

既存拡張の `URL再生` / `URL無限` と次行の `**【タイトル】**` を受信し、`URL直接` も受信します。URLの `t` / `start` / `from` / `time_continue` と `#t=` を開始位置へ変換します。将来の拡張用に次の形式も受け付けます。

```text
NYANPLAY/1 {"version":1,"type":"play","pageUrl":"https://www.nicovideo.jp/watch/sm123","title":"タイトル","startSeconds":12,"loop":false}
```

再生はアプリ専用のブラウザ・Cookie領域で行います。ユーザーのChromeを強制終了しません。再生先には設定したホストの通常のHTTP/HTTPS URLを指定します。ファイルURL、IPアドレス、localhost、未許可ホストは受け付けません。サイトのログインや再生操作が必要な場合は「再生画面」で操作します。サイトごとの特殊プレイヤーやDRMへの対応は別途検証が必要です。

Discord出力は再生ウィンドウの音声をAudioWorkletでPCMへ変換し、読み上げ音声と混合してOpusで送信します。PC全体のマイクやシステム音声は取り込みません。Discord.jsの現行音声ライブラリとDAVE実装を使用します。

## 保存と復旧

Windowsの `%APPDATA%/nyan-talk-damare` に設定、暗号化トークン、キュー、受信済みIDを保存します。設定とキューは一時ファイルからの置換で更新します。再起動時に処理中だった項目は「中断」とし、勝手に再生せず履歴から再試行できます。待機項目はBot開始・キュー再開後に処理します。最新500件の診断ログはメモリに保持し、認証値をマスクします。

Discord.jsによる回線断の再接続とWindows復帰時の再接続、音声切断の検知を備えます。自動接続を設定していても、無効トークン・Intent不足・音声エンジン停止を自動修正はしません。原因をイベントログで確認し、再開始・再試行してください。エンジンの異常終了後の自動再起動は未実装です。

## 開発と検証

```sh
npm ci
npm run check
npm run check:desktop
npm test
npm run smoke:desktop
npm run verify:audio
npm start
npm run dist:win
```

ソース開発にはNode.js 22.12以上。Windows配布物はWindows上でビルドします。CIはNode.js 24を使用し、コアテスト・Electron画面操作・Windowsパッケージ作成を行います。Linuxでは画面検証にXvfbが必要です。

自動試験はプロトコル、受信・権限・除外、永続化・復旧、辞書、キュー、8声種の模擬API、FFmpeg変換、音声混合、棒読みちゃんTCPを対象にしています。Electronの試験は画面起動、辞書フォームの保存、HTML文字列を実行しない表示を確認します。`verify:audio` は実アプリを起動し、合成APIのWAV試験素材を3回連続で再生、ダッシュボードの更新、動画・音声プレイヤーのミュート解除と自然終了、AudioWorkletのPCM取り込み、Discord用Opusエンコード後の非無音出力を検証します。Linux CIでは仮想出力デバイスの実出力も録音して確認します。`dist/audio-verification` にJSON結果と試験動画音声のWAVを保存します。実BotトークンでのVC到達、実VOICEVOXモデル、各SNSの認証条件、Windowsでの長時間運転は別途受け入れ確認が必要です。[機能対応表](FEATURE_PARITY.md)の未解決項目を含め、全統合元の全機能移植が完了した版ではありません。

## 共通再生・チャンネル切替・転送

「Discord接続」でマスタチャンネルのテキストチャンネルIDを保存します。そこのメディア要求を全ての参加VCへ共通再生し、通常再生は各サーバーごとに一時停止・復帰します。マスタ以外の要求はそのサーバーのキューで独立して進みます。設定したVC内のテキスト投稿も自動で受信します。

Dispeak風のサーバー別一覧で「チャットの読み上げ」「入退室・移動の読み上げ」と各チャンネルをチェックボックスで選択します。「すべて選択」は閲覧権限のあるチャンネルにだけ適用します。サーバーをOFFにしても各チャンネルの選択を保持し、再度ONにすると復帰します。チェックを外した登録済みチャンネルでもメディア要求・管理操作を受信します。マスタチャンネルの共通読み上げはサーバーのOFFに影響されません。Discordから `!nyan read-channel <ID> on` / `off` でも登録済みチャンネルを切り替えられます。

接続先VCの変更でも既存の読み上げチャンネルの選択を保持します。BotがVCへ接続中なら選択したVCへ移動し、サーバー設定を削除した場合はそのVCから退出します。既存設定はそのまま読み込み、サーバーの読み上げはON、入退室通知は従来の全体設定を引き継ぎます。サーバー別の通知チェックを変更すると個別設定を優先します。

「読み上げ転送」で送信元・宛先を選び、片方向・双方向・転送なしを設定します。宛先にはBotの音声接続先が必要です。音声を直接送信し、テキストチャンネルへ転送文を再投稿しません。

## AndroidとGoogle Play

Windows x64、BIOS/UEFIでのCPU仮想化、Windows Hypervisor Platformを前提にします。十分なRAM・数GB以上のディスク容量とGoogleへのネットワーク接続が必要です。

「Android」でバージョン一覧を取得し、安定版のGoogle Play対応イメージを選びます。選択した版の利用規約を再取得・確認し、同意して「セットアップ/更新」を押します。公式SDKツール、ADB、Emulator、イメージと、必要なJava実行環境をユーザーデータ内へ管理導入します。既存SDK/Javaのパスも指定できます。

起動するとアプリ内のAndroid画面をタップ・スワイプで操作できます。戻る・ホーム・アプリ履歴と文字送信を備えます。Google Playを開いて端末内でGoogleアカウントにログインし、アプリをインストールします。Googleパスワードをにゃんとーくの設定へ保存しません。アプリによりエミュレーター上の利用を制限している場合があります。

同じAPIレベルはEmulator・イメージを更新し、Androidバージョン変更は別のAVDを作成します。旧AVDを残すため、旧端末のアプリデータを自動消去しません。別バージョンへのデータ移行はGoogleのバックアップ等を利用します。仮想化機能がない環境での実起動は未検証です。

## Twitter / X

対象アカウントを複数、カンマまたは改行で入力します。RT、返信、過去投稿の初回読み上げ、取得間隔、出力サーバーを設定できます。既定では開始後の新着だけを読みます。本文のない画像/動画投稿・RTはスキップします。

X Developer PortalのAPI2利用権限が必要です。公開アカウントはAPI Bearer Token、非公開アカウントはOAuth2の本人ログインを使います。OAuthはPKCE対応の公開クライアント（Native App等）としてClient IDを設定し、コールバックを `http://127.0.0.1:11488/callback` に登録します。ポートを変更した場合は登録URLも変更します。

非公開はログインユーザーIDと対象アカウントのIDが完全に一致する時だけ読みます。フォロワーとして閲覧できる別人の非公開投稿は対象外です。ログアウトすると非公開投稿の待機・再生を中止し、保存されたジョブ本文を伏せ字にします。APIの利用枠・対象権限はX側の契約に依存します。

## テーマと棒読みちゃんの移行

ヘッダーの月／太陽アイコン、または Ctrl＋Shift＋L でライト／ダークを切り替え、次回起動にも保存します。アイコンにマウスを重ねると操作名が表示され、TabとEnter／Spaceでも操作できます。再生・更新・削除などはアイコン、保存・取り込みなどはアイコンと操作名で表示します。CSV nyaan Viewerのコンパクトな操作部を参考にし、配色はMicrosoft VS Codeの公式CSSとModernテーマの定義を使用します。装飾用の英語字幕・バナーはありません。

左上の猫画像を元に、Windows実行ファイル・インストーラー・アンインストーラー・ショートカット・ウィンドウ・トレイのアイコンを統一しています。Windows用ICOは16〜256pxの7サイズを同梱し、元画像のSHA-256を記録します。アイコンの再変換は `npm run icon:build`（Linuxは画面環境が必要）で行います。

「読み方の辞書」で棒読みちゃんのZIPを取り込み、元アプリを起動します。原本の全設定・辞書を保持し、原文をネイティブ辞書処理へ送るモードを備えます。現在はローカル音声の経路です。[取得設定・長文加速等の移行一覧](BOUYOMI_IMPORT.md)をリリース前の指定確認に使用してください。棒読みちゃん本体でのWindows実行比較は未完了です。

LAN端末からのブラウザ通話は [LAN音声設計](LAN_VOICE_DESIGN.md) に記載し、この版には実装していません。


## 元構成の再生・停止とBotアクティビティ

| 受信メッセージ | 告知 | 再生 |
| --- | --- | --- |
| `URL再生` | サービス名を読み上げてから開始 | URLの開始位置から45秒。先に終端へ達すればそこで終了 |
| `URL無限` | サービス名を読み上げてから開始 | URLの開始位置から終端まで1回 |
| `URL直接` / `!nyan direct <URL>` | なし | URLの開始位置から終端まで1回 |
| `ていし` | `さいせいをていししました` を優先読み上げ | 対象の処理中・待機中メディアを停止・取消 |

YouTubeは「ゆーちゅーぶを再生します」、ニコニコ動画は「にこにこどうがを再生します」、Xは「えっくすを再生します」、twitter.comは「ついったーを再生します」。Instagram、TikTok、Facebook、Threads、Bluesky、Discordの添付にもサービス別の読み方を使います。追加許可ホストは「メディアを再生します」。告知完了前に再生ウィンドウを開きません。告知中に停止した場合も再生を開始しません。

平文の「ていし」は管理コマンドの権限を要求せず、受信対象として設定したチャンネルで利用できます。読み上げ全体がOFF、または当該チャンネルの読み上げがOFFでも受信します。ユーザー・Bot・Webhookの受信ポリシーは適用します。処理中の当該サーバーの読み上げを中断し、待機中の読み上げより先に停止告知を流します。待機文章は保持し、停止告知後に通常の読み上げ設定に従って再開します。マスタチャンネルからの停止は共通メディアと接続済みVCへの共通告知として扱います。他のサーバーの独立メディアを取り消しません。

実際にメディアが再生状態に入ると、サービス名とタイトルをBotのアクティビティに表示します。音声は「再生中」、動画は「視聴中」のDiscord標準表示を使い、一時停止も表示へ反映します。アクティビティはBot全体で1つの表示なので、マスタ再生を優先し、それ以外は直近に開始したメディアを表示します。表示対象が終了したら残る再生へ戻し、全て終了したらクリアします。同じ表示を定期的に再送しません。

入退室・移動ログは「入退室を読み上げる」を有効にすると設定したVCの参加・退出・移動を読み上げます。VC内の音声を文字起こしする機能は対象外です。元構成との対応と残る差は [ORIGINAL_PIPELINE.md](ORIGINAL_PIPELINE.md) を参照してください。

## v0.4.3の読み上げ・再生修正

日本語アプリ名をElectronのHTTP User-Agentから除去し、サイト接続に使うヘッダーをChromiumの形式へ統一しました。これはYouTube以外の再生先とElectronのネットワーク取得にも適用します。サイトでミュートされた動画・音声は再生時に解除し、ブラウザの再生失敗と音声取り込みの切断をイベントログに表示します。

音声ストリームの終了後に、終了したミキサーへ新しい読み上げを追加して永久待機する不具合を修正しました。エンコーダーの短い音切れへの許容時間を増やし、ストリーム終了・進行停止を検知して待機を解除します。次の読み上げ・再生で音声接続を作り直します。画面の音声処理がタイムアウトした場合も再生を取消し、後続のキューを進めます。

デスクトップの読み上げ・メディア入力は、接続済みサーバーが1つならそのサーバーを選択します。接続がなく設定済みサーバーが1つの場合もそのサーバーを使います。複数の宛先がある場合は選択が必要です。送信先やVC接続の不備はキューへ追加する前に表示します。Discordチャット由来の処理は元のサーバーをそのまま使います。

公開サイトの実再生はWindows CIの別ジョブでYouTube `ro_v7LqdI58` とニコニコ `sm9` を試し、`audio-verification-live-sites` のJSONに**音声サンプルを確認できたか**を記録します。サイトのログイン要求・地域制限・CI拒否などの失敗は未検証として残します。配布物のビルド成功をサイト再生成功の根拠にはしません。
